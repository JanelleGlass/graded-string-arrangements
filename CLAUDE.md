# Graded String Arrangements (website)

Janelle's free public website: hymns and carols arranged in six levels for violin, viola,
cello and bass, each with a play-along reader. Janelle is a Suzuki strings teacher, not a
programmer: tell her what changed on the page, not in the code.

- Live: https://graded-string-arrangements.vercel.app
- Repo: https://github.com/JanelleGlass/graded-string-arrangements (public: never commit anything
  that isn't meant for the website, such as PDFs for sale, scans, or her build tools)
- Hosting: Vercel, connected to this repo. **A push to `main` goes live by itself in about a
  minute.** So push only when Janelle has seen the change and said to.

This folder normally sits inside her `Music Arrangements` folder (as `website/`), where the
arrangements are built. Arrangement rules live in `../BUILD-SPEC.md`, not here.

## What's where

| Path | What it is |
| --- | --- |
| `reader/reader.html` | The master reader: one file of HTML, CSS and JavaScript (alphaTab 1.8.4 from jsdelivr). Edit the reader here and only here. It is also the private Claude preview (see below), so it starts at `<style>` with no `<html>`/`<head>`. |
| `songs.json` | One entry per song, in home-page order. Fields are explained at the top of `tools/build_site.py`. |
| `songs/<slug>/<slug>.xml` | Each song's score: the finished 24-part MusicXML, copied from the Music Arrangements folder. |
| `songs/<slug>/index.html` | Generated by the build. Never edit by hand. |
| `index.html` | Home page, written by hand, except the song cards between `<!-- songs:start -->` and `<!-- songs:end -->` and the app script between `<!-- app:start -->` and `<!-- app:end -->`, which the build writes. |
| `assets/` | Music font (Bravura) and string sounds (GeneralUser GS), with licences, and the site icons. Shared by every song. |
| `manifest.webmanifest` | Lets phones add the site to the home screen as an app that opens without the address bar (icons: `assets/icon-*.png`, `assets/apple-touch-icon.png`). Linked from the home page head and the build's `HEAD`. A new icon also goes in `APP_FILES` in `tools/build_site.py` (the build says so). |
| `app/app.js` | The app layer every page loads: starts the offline copy, lets iPhones play through the ringer switch, and shows the home page's "Install the app" button where the browser offers one. Kept out of the reader on purpose (see "The app version" below). |
| `sw.js` | The offline copy (service worker). Generated by the build from `tools/sw_template.js`. Never edit by hand. |
| `tools/build_site.py` | Builds the song pages, the home-page cards and `sw.js`. |
| `tests/smoke.py`, `tests/mockroom.js` | Browser test of the site, the conductor and the app version (install, offline, updates). |
| `.vercelignore` | Keeps the working files above off the live site. |

Commands (on Janelle's Windows PC use `python`; elsewhere `python3`):

    python tools/build_site.py
    python tests/smoke.py

The test needs Playwright once per computer: `python -m pip install playwright` then
`python -m playwright install chromium`. To look at a page yourself: `python -m http.server 8000`
in this folder, then http://localhost:8000/ .

## Adding a song

Only after Janelle has checked the finished arrangement in the Music Arrangements folder.

1. Copy the finished file to `songs/<slug>/<slug>.xml` (slug: lowercase-with-dashes, e.g.
   `holy-holy-holy`). Copy only the 24-part file, nothing else from her folder.
2. Add the song to `songs.json` (title, category for the home card, collection, source line,
   `pdf_url` empty until there is a Payhip link).
3. Run the build. It reads key, time, bars and the written tempo from the score, and stops if the
   parts aren't the 24 the reader expects, in BUILD-SPEC order (level by level; violin, viola,
   cello, bass within each level). Tell Janelle what it read so she can catch a mismatch. It also
   adds the song to the offline copy (`sw.js`), so installed copies get it on their next open.
4. Run the test. Show her the page (local server, laptop and phone sizes) before pushing.
5. Commit and push when she says go. Then check the live page loads.

## Changing the reader

1. Edit `reader/reader.html`.
2. Build, then test. For anything visual, also take screenshots at laptop (1366x860), phone
   landscape (844x390, 667x375 for iPhone SE) and phone portrait sizes, and look at them.
3. Update the Claude preview: publish `reader/reader.html` as an artifact to
   https://claude.ai/artifact/WqVvah4mND1xSPHvPpybTv (pass that URL so it updates in place).
   Don't change its capabilities: it uses the `room` capability for the conductor. Its score,
   font and sound files are already published there and are kept.
4. Push when Janelle says go.

If a reader change touches one of the song-specific strings the build swaps out (title, About box
facts, `SCORE_URL`, `BASE_TEMPO`, `TEMPO_PERCENT`, the storage key, the Buy-note line, the title wrapper), update
`TEMPLATE` and `song_page()` in `tools/build_site.py` too. The build stops with a clear message if
one goes missing.

## The two versions of the reader

- **Claude preview** (the artifact above): plays The First Noel, and has the conductor ("Play
  together": the teacher's device leads, students' devices follow) through `window.claude`.
- **Public site**: the same reader built per song. `window.claude` doesn't exist there, so the
  conductor hides itself. Planned later: a conductor on her own site, which needs a backend
  (Supabase) and a teacher login. Also planned: a separate door for her own students, linked from
  her teaching site, and Buy buttons once PDFs are on Payhip (`pdf_url`).

## The app version (home screen, offline)

Added to a home screen ("Install the app" in Chrome, Edge and Android; Share, then Add to Home Screen
on iPhone and iPad), the site opens like an app. After one visit every song works with no internet.

- The offline part lives in `app/app.js` and `sw.js`, wired in by the build. The reader itself has no
  app code, so `reader/reader.html` and the Claude preview are untouched. Keep it that way: the same
  layer will be reused for the app-store versions (Google Play, then the App Store through
  Capacitor), where `app/app.js` skips the offline copy because the app carries its own files.
- What is kept offline: the home page, every song page and score, the Bravura font, the string
  sounds, the icons, alphaTab from jsdelivr, and the Google Fonts lettering (Latin letters). About 8 MB
  with two songs. Each new song adds its score (1 to 3 MB). Once that passes about 50 MB, switch to
  keeping only the songs a student has opened.
- Updates: the build writes a fingerprint of every file into `sw.js`. After a push, an installed copy
  picks up the change the next time it is opened online, and downloads only the files that changed
  (a new song doesn't re-download the 4 MB of sounds). Pages come fresh from the network when it
  answers within 3.5 seconds, so a new song shows up on the home page straight away.
- Score, font and sound addresses carry their fingerprint (`?v=...`), so a page never mixes an old
  score with a new page.
- iPhone: `navigator.audioSession.type = 'playback'` lets the music play with the ringer switch off
  (iOS 17 and later). Older iPhones stay silent on mute; there's nothing more to do there without a
  native app.
- App icon: the white note on teal (`assets/icon-*.png`, `assets/apple-touch-icon.png`), the same as
  the browser-tab icon. Janelle chose it over a design with the open strings in their colors (2026-10-16).
- `sw.js` lists every song page's fingerprint. When sessions commit separately, whoever commits second
  rebuilds and commits `sw.js` with the song pages.
- The Claude desktop browser pane supports offline copies. Use the `website-app-8030` entry in
  `../.claude/launch.json`: the other entries hard-code ports that other sessions are often using.

## Decisions Janelle has made about the reader (keep them)

- Line view: the music starts at the left edge with no lead-in space and the clef is never cut off;
  the playing note sits a third of the way from the left so students see what's coming. Music is
  top-aligned under the header.
- Every setting is always visible in a strip at the bottom, on phones too, never covering notes.
  Zoom − / + lives in that strip (0.3x to 1.75x). Phone-landscape buttons are compact so the strip
  fits one row on regular iPhones.
- Parts: a quiet bump-out tab on the right edge of the screen, halfway down the music (a chevron
  and "Parts", read sideways, in soft grey; 34px wide, 136px tall), with swoopy sides: its top and
  bottom curve smoothly into the screen edge (and into the panel's edge when open). It slides a
  panel in from the right, from the top of the screen down to the strip. There is no Parts button in the strip. The tab rides along the panel's edge while it's
  open and closes it again (so does ×). Closed, the music runs a little under the tab (it
  overlaps the music by about half its width), on a wide screen too, past the centred page. Open, the panel slides over the music, which stays where it
  is and runs on behind it (Janelle's choice: an earlier version moved the music over beside the
  panel). Pointing at the tab names the part on the page, or "3 parts". Phones show short
  level names ("Adv. melody") to keep the panel narrow. The panel holds one table: a
  level on each row and an eye for each instrument (See), headed Vln, Vla, C, B (Janelle's
  choice: C and B, not Vc and Cb; the staff labels keep Vc. and Cb.). Every part is on the page or not on its
  own, so a violin at Open Strings can read with a cello at Advanced Melody. Parts show in score
  order; one part always stays on the page. The table scrolls, fading at the bottom, when the
  screen is short.
- Hear: a "Hear the parts I see" checkbox under the table, ticked by default, works like "billing
  address same as shipping". Ticked, the parts on the page are the parts that play. Unticked, a
  Hear speaker for each part appears beside the eyes (headed "Hear") and chooses what plays, so the
  tune can play on one instrument while Harmony keeps all four (that balance is the point: the tune
  doubled four times drowns the rest) or a student can leave their own part out. Unticking it the
  first time starts the speakers from what's playing; ticking it plays the parts on the page again;
  unticking it again brings back the speakers' mix, which also keeps playing with the panel closed.
  The heading over the eyes is always "See". A first visit shows and plays Violin Melody. A student
  following the teacher sees only the eyes. Phones show whatever the eyes say.
- History of Parts (2026-10-16): it began as an instrument list and a level list, each with an eye,
  plus a speaker per instrument; Janelle dropped the instrument speakers as redundant, then the
  instrument list, because separate eyes forced every chosen instrument at every chosen level; then
  folded the speakers away so students see only the eyes unless they want a mix. A sideways Hear
  tab with a "See & Hear" heading came first; she replaced it with the checkbox because eyes under
  "See & Hear" didn't say they play sound and the tab didn't say what it did.
- Metronome is one button that cycles Off → On → On with count-in → Count-in only.
- Tap a note to choose where Play starts: a thin, pale ring around the note head until the music
  starts. No flag.
- Drag across bars (on touch: press, hold, then drag) to loop them. Tapping outside the loop clears
  it; tapping inside moves the start within it. At the loop end: stop, rest one beat, slide back so
  the first note is at the playing spot, count in if count-in is on, and go again. Nothing sounds
  or lights up past the loop end. There is no separate practice-loop panel.
- Counting: one straight row of counts under the staff, soft grey, "&" the same as the numbers,
  the current count in teal bold, no circles or pops. Held notes join their counts with a line
  (ties too, rests not). Dynamics sit below the count row. A "Counting" toggle sits just before the
  first count and sticks to the left edge when scrolled. The count-in overlay is the same size,
  lighter.
- Hover (mouse) or tap (touch) explains the clef, each sharp or flat in the key signature, the time
  signature and dynamics.
- Full screen: a button at the end of the bottom strip, shown only where the browser allows it (Android,
  iPad, computers). iPhones don't allow it, so there the button is hidden; instead the site can be added
  to the home screen and opens without the address bar. The home page has a one-line tip saying how
  (it also says every piece then plays without the internet), with an "Install the app" button under
  it only where the browser can install in one tap.
- Open Strings parts show string colors but no finger numbers.
- alphaTab's "rendered by alphaTab" line is hidden; alphaTab is credited in the footer.
